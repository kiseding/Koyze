# ADR-0001: 选择 Cloudflare Workers 作为同步后端

## 状态
已接受

## 上下文
Koyze 需要一个轻量级后端来处理：
- 用户账号与认证
- 跨设备歌单同步
- 收藏列表云端存储
- 用户偏好设置同步

但我们不希望：
- 运维传统服务器（成本、维护负担）
- 代理音乐搜索/播放/歌词请求（隐私问题、带宽成本）
- 要求用户自行部署复杂后端（降低使用门槛）

## 决策
使用 **Cloudflare Workers + D1 + KV + Durable Objects** 作为同步后端

技术栈：
- **Workers**: Serverless 计算（处理 HTTP 请求）
- **D1**: SQLite 数据库（用户、歌单、同步事件）
- **KV**: 键值存储（会话令牌、缓存）
- **Durable Objects**: 有状态对象（速率限制）

## 理由

### 优势
1. **零运维 Serverless**
   - 无需管理服务器
   - 自动扩展（按请求量）
   - 全球 CDN 分发（低延迟）

2. **慷慨的免费额度**
   - Workers: 100,000 请求/天
   - D1: 100,000 读取/天, 50,000 写入/天
   - KV: 100,000 读取/天, 1,000 写入/天
   - 对于小规模应用完全够用

3. **简单部署**
   - Wrangler CLI 一键发布
   - 无需 Dockerfile/Kubernetes
   - 内置密钥管理（Secrets）

4. **开发者友好**
   - TypeScript 支持
   - 本地开发环境 (Miniflare)
   - 迁移系统内置

5. **隐私友好**
   - 只存储用户账号和歌单数据
   - 不代理音乐内容（不触碰版权内容）
   - 用户可选择不使用云同步

### 劣势与缓解
| 劣势 | 缓解措施 |
|------|---------|
| D1 仍在 Beta | 已接近生产就绪；提供备份端点 |
| 依赖 Cloudflare 生态 | 数据可导出；迁移脚本可编写 |
| 冷启动延迟 | Workers 冷启动 < 50ms，可接受 |
| 单一供应商锁定 | 接口抽象化，可切换到自托管 |

## 替代方案

### 1. Firebase
**优点**: 成熟、集成认证、实时数据库  
**缺点**: 
- 需要 Google 账号
- 中国大陆访问受限
- 定价复杂

### 2. Supabase
**优点**: 开源、PostgreSQL、实时订阅  
**缺点**: 
- 需要运行 Postgres 实例
- 免费额度较小
- 成本随用户增长快速上升

### 3. 自建 Node.js + MongoDB
**优点**: 完全控制、无供应商锁定  
**缺点**: 
- 需要运维服务器
- 需要配置 HTTPS/域名/防火墙
- 用户难以自部署

### 4. 不提供后端（仅本地）
**优点**: 最隐私  
**缺点**: 
- 无法跨设备同步
- 用户数据仅在本地（易丢失）

## 后果

### 积极影响
- ✅ 用户无需部署或配置服务器
- ✅ 成本可控（小规模免费）
- ✅ 全球低延迟访问
- ✅ 开发者可快速迭代

### 消极影响
- ⚠️ 依赖 Cloudflare（缓解：提供数据导出）
- ⚠️ D1 Beta 阶段可能有 breaking changes（缓解：固定版本、迁移脚本）
- ⚠️ 超过免费额度需付费（缓解：清晰的成本预测文档）

### 技术债务
- 如果未来需要迁移到其他后端，需要重写 Workers 逻辑
- 缓解：使用抽象层（Repository Pattern）
